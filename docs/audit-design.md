# Quoin 自动审计与操作关联设计

- 日期：2026-09-14。
- 状态：已落实为代码与机器契约；实现、检查和隔离部署的实际验收结果见[实施计划](auth-audit-implementation-plan.md)及[验收记录](acceptance/auth-audit-20260915/README.md)。依据 [ADR-0006](adr/0006-automatic-audit-and-operation-correlation.md)。
- 与[统一认证设计](authentication-design.md)共同构成认证、权限与审计基础；具体接口以同步更新的 SQL、OpenAPI、Runtime proto 和部署契约为准。

## 1. 目标与当前差距

新增业务功能即使不调用任何审计函数，也必须通过统一执行路径自动产生审计。缺少必要声明或绕过路径应被注册校验、受限数据库能力和 CI 拦住，不能依赖开发者记忆或逐功能补测试。

整改前认证和各业务分别维护审计 INSERT，备份与认证管理命令具有可复用的同事务台账模式。整改后由 `execution.Run` / `execution.Execute` 统一提交权威结果，准入框架记录访问事实。表级不可变约束只能保护已经存在的记录；完整性还依赖操作声明、受控事务、真实只读连接及架构和行为检查，不能只靠导出审计函数、手工调用规范或 HTTP 状态码日志。

## 2. 默认审计的两个执行位置

### 统一入口：访问事实

HTTP、流式、下载、认证及其他入口统一注册操作，自动获取请求关联、主体和准入结果。用户查询默认记录访问元信息，不复制查询结果；已认证权限拒绝自动记录。敏感查看、凭据读取、下载和导出在释放内容前持久化访问授权审计，失败则拒绝释放。普通必需访问审计也不能在写入失败时静默放行。

请求已接受、访问已授权、响应传输完成、业务状态已提交是不同事实。下载开始不等于下载完成；流式连接不逐帧或逐心跳写审计。HTTP 中间件不能把响应码当作数据库提交事实，也不能承担业务与审计的原子提交。

审计页面查询自身可以产生一次访问记录，但审计基础设施写入记录不能递归触发新的审计；保留策略调整和清理批次则是独立系统操作。

### 统一命令执行器：权威业务结果

新增、修改、删除、初始化、密码重置等状态变更走共享执行器：建立操作上下文 → 开启事务 → 复检权限/状态及幂等 → 执行业务 → 自动记录命令结果与成功审计 → 提交。

业务实现不负责调用审计、提交或回滚。审计失败导致业务修改回滚。确定性拒绝不能携带意外业务修改提交，应在干净事务中持久记录拒绝；实现复用现有拒绝与命令台账语义。数据库不可用或提交结果不确定时只报告可证实的诊断，不能伪造持久拒绝或成功。可恢复的认证失败计数等属于显式状态变更，与拒绝事实一并按其事务契约处理。

同一命令重放不重复产生业务成功事件；本次访问可以另有访问记录并引用原命令结果。无实际修改的人类命令仍记录其提交事实。后台 CAS 竞争或空闲扫描可由 `Execute` 返回 `ErrNoTransition`，执行器回滚保存点且不生成事件；`Run` 不接受该哨兵，授权与上下文校验仍先行，不能将其作为任意关闭审计的开关。

外部短信、RPC、文件等副作用不因同库事务自动获得原子性，必须区分受理、尝试、确认等事实，沿用对应任务/投递的幂等及恢复规则。Artifact 物理清理先提交有明确对象的删除意图，再在写事务内重新检查引用后删除文件并同步目录，最后提交完成记录。意图写入失败时不得删除；文件删除后的完成审计或提交失败，只保留已确认的意图，不伪造成功，也不在下一次发现文件缺失时倒推出历史删除成功。

## 3. 强制执行而不是开发约定

- 所有操作注册必须提供稳定标识、权限、读写类别和对象定位契约；新建对象从类型化结果获取 ID。缺少声明在注册或公共契约测试失败，不从 URL/SQL 猜测业务语义。
- 操作者、来源、时间、结果及关联信息由基础执行路径自动提供。业务无需重复传入，客户端不能冒充主体。
- 查询通过只读数据库能力。`execution.Reader` 是不透明具体类型，仅由 `OpenReadOnly` 创建，所有池连接均以 SQLite `mode=ro` 打开；任意原始池或包装不被接受，不能以一次连接级 PRAGMA 检查代替池级保证。业务修改仅接受具体 `*execution.Tx`（`Executor` 为其指针别名），不能通过嵌入接口转发到裸连接；事务结束后句柄失效。业务不得自行打开可写连接或提交事务，读快照也不暴露原始连接。
- 缺少合法执行上下文的受审计操作拒绝执行，不能临时生成无关联 ID 掩盖缺口，不能默认假定为系统操作。
- CI 检查注册覆盖、可写连接创建/事务提交位置和依赖约束；公共测试验证自动审计、回滚、拒绝及重放。单纯 grep 不构成全覆盖证明，结合受限接口和行为测试。
- 不建设任意 audit:false 配置。高频遥测等例外集中声明类别和理由，接受审查和覆盖检查；新增未知类别不默认豁免。

这些约束防止正常开发遗漏，不声称能阻止有权修改源码或直接管理数据库的人蓄意绕过。

## 4. 覆盖与例外

| 类别 | 行为 |
| --- | --- |
| 用户增删改、管理命令 | 自动记录权威结果，成功与状态同事务 |
| 用户查询 | 默认访问元信息，不记录结果正文或原始筛选值 |
| 敏感读取、导出、下载 | 释放内容前记录授权访问，传输结果单独区分 |
| 初始化、密码/二级验证、恢复、会话 | 认证流程自动记录阶段和结果，秘密排除 |
| 调度、CLI、维护及后台管理操作 | 在入口建立明确系统/服务主体及来源，走共享执行路径 |
| 心跳、健康检查、高频观测或遥测数据 | 集中分类的例外，不逐条复制为业务审计 |
| 匿名爆破、无效令牌、畸形请求和限速 | 有界安全日志/指标，不无限写业务审计表 |

已明确关联账户的验证失败按统一安全事件规则记录并限制重复事件量；匿名声称的用户名不能当作已认证主体。例外不能免除真正的用户命令和敏感访问审计。任务已受理与完成分别记录，不能把排队成功当成执行成功。

## 5. 关联 ID 与生命周期

### 标识职责

- correlation_id：一次完整业务操作的关联标识，由可信操作入口创建。
- event_id：每条审计事件的唯一标识。
- request ID、client_command_id、任务 ID、Attempt ID：复用现有标识，分别表达请求、幂等、任务和执行尝试，不被 correlation_id 替换。
- 原始发起者与当前执行主体：后台代执行时分别保留，不能把当前系统执行伪装成人类会话仍有效。

不把整段登录会话当作一次操作。同一用户会话的多次独立操作有不同关联；周期调度每次触发是新操作，任务内部重试继承原关联。确需跨独立操作追溯时保留明确前序引用，不无限沿用一个 ID。

### 同进程

通过项目私有键和类型化访问函数在 Go context.Context 中携带不可变关联元信息，调用链继承，不使用可碰撞字符串键。Context 只承载请求范围元信息与正常取消/deadline，不作为依赖容器或权限证明，不存密码、OTP 或令牌。

入口负责创建上下文；子步骤不得悄悄替换关联 ID。审计和日志基础设施自动读取，业务函数只需遵循既有接收 ctx 的约定。权限始终来自认证与当前服务端状态，敏感写继续复检。

### 跨请求、后台及重启

HTTP 请求结束后不能继续依赖原请求 Context。创建持久任务时，在同一事务中保存 correlation_id、原始发起者引用与任务来源；后台使用任务取消和截止规则管理的新 Context 恢复元信息。进程重启后从任务状态重建，不通过永久保持请求或随意脱离取消来解决。

一次登录跨密码、发送验证码、重试校验和会话签发请求时，关联 ID 保存在服务端认证流程里；只有合法流程凭据才能找到该关联，客户端不能指定别人的流程。流程完成后终结；初始化后的重新登录创建新关联，可引用前序流程。幂等重放从持久命令记录读取原业务关联，本次请求标识仍独立。

### 跨进程与信任

使用受控 HTTP/gRPC 元数据或持久消息/任务字段显式传播；Go Context 不自动跨网络。接收方在校验服务身份、任务归属和协议后建立本地上下文，限制字段大小和格式。公开客户端提交的关联头不能冒充内部主关联或主体；外部供应商若支持关联，可传递非秘密标识，不要求增加不支持的字段。

取消、超时、授权和关联分别处理：继承 correlation_id 不意味着继承已过期用户权限，也不意味着父 HTTP 请求取消必须取消已受理任务。跨重试保留主关联，按既有 Attempt 区分物理尝试；并发事件按因果引用和记录顺序解释，不声称跨进程时间戳形成精确全序。

## 6. 保存、隐私与展示

审计模块位于 `internal/quoin/audit`，负责统一持久化和查询；触发责任属于统一入口、认证流程和执行器，不向业务要求主动调用。继续与业务同 SQLite 数据库，避免异步投递后才补成功审计。审计不是业务事实唯一来源，不采用事件溯源，也不是必须上报的外部跟踪平台。

记录主体引用、动作、目标类型/ID/适用版本、阶段、结果、服务端时间、correlation_id 及已有请求/命令/任务引用。字段白名单，禁止默认序列化请求/响应、headers、任意对象、验证码、密码、凭据、提示词或联系方式全文。错误先映射稳定代码，不保存供应商原始响应。

仅管理员从“系统管理 → 审计日志”进入统一页面，可按时间、主体、类别、对象、结果、关联 ID 筛选；关联详情展示发起、准入、执行尝试和结果。关联不授予额外数据权限，不能仅凭 ID 读取记录。界面明确保留期、清理状态与已知历史缺口，不把缺失/过期事件伪装为完整链路。个人账户不放全局审计入口。

## 7. 保留与清理

默认且最短六个自然月，可延长至 240 个月。部署 YAML 的 `audit.retentionMonths` 只提供首次空库引导的初值；运行权威是数据库单例设置，重启不得覆盖管理员修改。示例值为 6/12/24，小于 6 拒绝。服务端 UTC 记录时间，减自然月时日期夹到目标月份最后有效日，避免把半年默认为固定 180 天。

内容不可修改，保留期内不可删除。迁移已将原无条件禁止删除触发器替换为到期保护与受控清理机制，未放松其他不可变历史的约束；数据库继续保护未到期记录，内部清理限定可删除的到期集合。UI/API 不提供单条删除、任意批量删除或清空。

清理分批处理过期事件及目标关联，避免长事务；与相关批次记录原子提交，记录截止点、范围摘要、数量和结果，不复制已删内容。失败保留数据并告警，不宣称清理成功。保留策略变化记录审计；缩短时展示影响并确认，后台再执行，不低于六个月。延长不恢复已删除数据。

以事件记录时间决定到期，不以操作终结时间代替；长期任务的早期事件可能到期，关联视图须如实呈现可用范围。清理不会取消仍在运行的任务或删除其权威关联信息。

备份保留独立于在线审计保留，在线删除不等于备份销毁。历史恢复后继续按当前生效策略运行受控清理；严格销毁要求需另行覆盖备份介质，不在本设计暗示已经满足。

## 8. 迁移与验收

替换分散手工审计写入，推广既有认证/备份命令事务能力到共享执行器；同步 HTTP、认证流程、查询与敏感读取、任务、CLI、维护、协议字段和 schema。旧审计没有可靠关联时保留“历史无关联”，不得按用户名/时间猜测填入。旧历史不能因迁移立即被静默批量删除，保留期切换应明确显示影响并经过受控流程。

验收必须证明：

1. 新增标准业务命令不写审计调用也自动产生事件；新查询自动有访问元信息。
2. 缺失操作声明、执行上下文、非法写连接或自行提交被拒绝/检查拦截。
3. 审计写入失败回滚业务，确定性拒绝不提交业务修改，提交未知不伪造结果。
4. 幂等重放不重复成功审计；并发请求、后台重试保留主关联并区分尝试。
5. 敏感读取审计失败不释放字节，流传输中断不记录完整下载成功。
6. HTTP 请求结束、任务跨进程及重启后仍保留 correlation_id，且取消/权限规则不被关联传播绕过。
7. 多步登录继承流程关联，重新登录与独立操作创建新关联；客户端不能伪造内部关联和主体。
8. 匿名/遥测例外有界，不漏掉用户操作；审计自身写入不递归。
9. 密码、OTP、Cookie、供应商鉴权及响应中的测试秘密不进入审计和日志。
10. 六个自然月及月末/闰年边界正确，未到期删除受保护，分批清理失败可恢复，备份边界明确。

对应实现、迁移、回归与真实浏览器证据已汇总在[实施计划](auth-audit-implementation-plan.md)、[操作覆盖清单](auth-audit-operation-coverage.md)及[验收记录](acceptance/auth-audit-20260915/README.md)。本地验收不等于生产备份恢复、正式回滚资格或真实外部邮件/短信送达验证；这些边界在验收记录中分别说明。
