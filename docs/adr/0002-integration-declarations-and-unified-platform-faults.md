# 以接入引用、任务触发采集和独立来源统一平台故障

[GitHub #95](https://github.com/Suknna/quoin/issues/95) 已接受：接入是运维中心中的用户侧平台入口，业务系统由同一份可通过表单或 YAML 编辑的权威声明显式引用接入并限定用途与范围；因此不再保留 YAML-only、全局唯一 Thanos、仅业务内创建浏览器身份或独立周期资源刷新的领域定义。浏览器身份独立配置且默认不跨业务复用；其引用必须明确授权，profile 与秘密仍隔离于前端、业务声明、日志和模型。平台内部故障以独立来源映射进入统一告警读模型，不伪造 Alertmanager Delivery、Occurrence 或业务归属；内部组件只由管理员在设置“关于”中查看和维护。各切片实施时必须同步替换冲突的 API、Schema、SQL、Runtime、测试和文档，不保留双模型兼容路径；不能以其中一个切片交付代表整个 #95 已完成。

## #102：组件事实与故障历史分离

管理员“关于”汇总当前组件事实及原有注册、凭据退休和维护动作；统一告警保留平台故障的独立历史身份。采用现有 Runtime 事实投影而不是引入另一套健康采集器，避免把连接事实推断成业务健康。没有可靠版本或状态时明确显示未知。

平台故障没有 Alertmanager Delivery 或 Observation，也不自动获得业务归属。当前平台故障不支持初步分析，前端说明原因、服务端拒绝创建业务分析；不能用假的上游事件或业务配置填补能力缺口。组件恢复更新原故障并保留已打开详情，不删除历史。普通用户只可读取允许公开的组件、固定非秘密原因和生命周期时间，不获得关于页、维护清单或凭据操作权限。
