# ADR 0014: 小核心与事件式接入插件

- 状态：实施中
- 日期：2026-09-28
- 关联：#110
- 扩展：ADR-0004、ADR-0011、ADR-0012

## 背景

现有插件能在 Stele 解析 webhook、在 Quoin 注册外部工具与采证目录，但 Quoin 的交付入口、告警源、连接凭据、工具授权与巡检执行仍按平台或工具名称分支。这不满足新增常规来源只实现插件、无需修改告警分析和日报巡检主流程的目标。

## 决策

Quoin 继续是业务库唯一写者，负责可靠摄取后的领域投影、鉴权审计、告警生命周期、证据与任务状态、日报封存；Stele 保持外部网关与事务入队即 ACK；Plinth 只接收冻结任务和工具目录。插件是编译期装配、启动期冻结的受信任代码，部署配置控制启用集合；实例启停不等于代码热加载。

入站插件声明可生产的稳定 `(source kind, event type, payload version)`；Stele 只入队声明过的事件，Quoin 只消费已注册且已启用的来源和事件版本。规范告警投影由 Quoin 统一持久化；插件负责把平台协议转换为规范载荷，不得写权威业务库。告警插件声明固定的身份模式：Alertmanager 使用可由完整 labels 复算的 8 字节 fingerprint，其他来源可使用原始 externalId 与 32 字节 SHA-256（按来源隔离，首观测冻结，冲突项记录接入问题），绝不让每条事件自己选择模式。未知必需投影不 ACK 为已处理；传输暂时不可用可重试，确定性契约错误隔离或入死信。单事件的传输幂等键、来源内告警发生身份、定时计划边界键分别管理，不混用。

当前运行时实现以编译装配的来源 ID、插件版本、事件类型和身份模式生成清单指纹：Stele 每次拉取凭据快照与投递队列事件时携带它，Quoin 在 mTLS 准入后要求完全一致；不一致时 Stele 不会变为入站就绪。它不是身份凭据，不能替代 mTLS。已入队的旧版本事件尚未携带独立载荷版本；不同版本组件发布需要同批更新并预先排空 Stele 队列，后续须补齐每事件版本迁移或隔离策略，不能将清单一致误解为历史队列兼容。

插件可订阅有限的后提交事实，如告警观察已提交、日报时间窗到期、证据已提交、报告已封存。每个事实携带稳定版本、ID 和不可变引用，不携带秘密或无限正文；订阅方按 `(subscriber, event ID)` 幂等，失败有界重试并可重放，不能改变已完成的入站裁决或绕过 Quoin 写命令。复用现有队列与执行器，不建立无边界通用事件总线。

外部平台只通过 Quoin 授权后的 PlatformCaller 经 Stele 出站。平台插件声明适用的连接种类、现有受控 HTTP 认证方式、工具与采证模板的执行契约；Quoin 冻结授权与证据输入、Stele 注入凭据、Plinth 永不获得外部平台秘密。非 HTTP 传输和新增认证方式仍须独立安全设计，不能保证不改核心。

日报按管理员配置的时区与本地触发时间创建。每次触发汇总最近一个**已完整结束**的本地自然日 `[00:00, 次日 00:00)`，并把按时区计算的 UTC 边界、来源与计划版本冻结。触发后两小时为采证截止；即使封存实际运行晚于此刻，结果是否纳入也只按**结果提交时间不晚于冻结截止**裁决。未完成项明确记录 gap，已封存报告不可改写，迟到结果只能留存为任务事实；人工重分析的新版本也沿用原截止，不把迟到数据纳入日报。缺模型时仍保留已采证事实，不推断健康。不自动补跑服务停机期间错过的调度边界。

管理目录与通用配置表单从插件能力及封闭 schema 派生；用户侧只消费规范告警、Evidence 与日报读模型。正常新增来源/工具/检查项只修改插件包、两宿主编译装配与契约测试。

## 与既有 ADR 的关系

保留 ADR-0011 的三角色边界、编译期装配及 Stele 本地持久入队后返回 202；保留 ADR-0012 的归一化、静态富化、去重和视图关联。这里取代现有实现及文档中“只有 Alertmanager 能入站”、“只有 Prometheus/Thanos 能被网关执行”的限定，并把 ADR-0012 的“新告警来源 Quoin 零改动”落实为经规范载荷与已注册投影的能力，而不是允许插件任意写表。旧 SQLite 历史不迁移；实际清库需要部署操作者先确认目标环境、备份和维护窗口。

## 验收

使用一枚测试插件从 Stele 入站、Quoin 规范落库、触发告警分析并参与跨来源日报，检验同一事务的审计与幂等、两小时缺口封存、Agent 只看冻结证据以及禁用后历史可读；全过程不修改两条业务主流程。
