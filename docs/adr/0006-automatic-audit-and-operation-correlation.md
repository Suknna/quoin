# 默认自动审计与业务操作关联

2026-09-14 确认审计应是操作执行的默认行为，不能依赖业务开发者主动调用审计包。统一入口自动记录访问与拒绝，统一命令执行器将业务修改、命令结果和成功审计同事务提交；通过受限数据库访问、完整操作注册和架构检查阻止遗漏与绕过。复用既有命令台账和事务模式，不引入事件总线、外部审计平台或事件溯源架构。

一个 `correlation_id` 贯穿一次完整业务操作：Go Context 承担进程内传递，持久任务/认证流程及协议承接跨请求、进程和重启传播。延续的是关联身份，不是原请求 Context、取消信号或授权。关联 ID 不替代事件 ID、命令幂等键、任务和 Attempt ID，也不作为权限凭据。

审计入口统一为“系统管理 → 审计日志”，仅管理员可见。默认且最低保留六个自然月，可延长；内容不可修改，保留期内不可删除，过期仅通过受控清理执行。在线保留与备份生命周期分开。

## 状态与替代范围

本决定及[详细设计](../audit-design.md)已落实为统一执行器、准入、保留约束及机器契约，最终部署验收状态见[实施计划](../auth-audit-implementation-plan.md)。它补充 [ADR-0005](0005-unified-authentication-foundation.md)，替代旧规格中依赖各模块主动写审计、结构化审计无期限保留和头像菜单全局审计入口的设计。既有历史事实保持不变，代码整改与文档确认分别留有验证记录。

既有审计不伪造缺失的关联 ID 或操作者；迁移保持其历史事实。新机制须同步认证、业务命令、查询、下载、后台任务、CLI、维护、协议、保留期约束及公共验收测试，不仅增加一个审计工具包或 HTTP 中间件。
