# 唯一管理员与统一认证基础

2026-09-14 确认重新设计 Quoin 的登录、用户初始化、二级验证和认证扩展。采用唯一内置 Admin、多 Operator、服务端权威会话与统一认证流程；验证码投递通过 SMTP 或部署方配置的出站 HTTP Webhook，不引入强制第三方身份或通知平台，也不由 Quoin 维护各家短信网关适配器。

本决定是已确认的目标设计；统一认证流程的代码与机器契约已落地，迁移与验收仍在进行。详细流程、约束和验收范围见 [统一认证设计](../authentication-design.md)。审计默认自动记录机制随后由 [ADR-0006](0006-automatic-audit-and-operation-correlation.md) 确认并补充，本 ADR 不重复定义该机制。

## 取舍

- 空库首次启动自动创建待初始化的 `admin`，初始密码 `admin` 只能用于受限初始化。远程初始化还必须证明部署所有权；本机受限的一次性安装凭据用于阻止公开默认密码被抢先使用。（superseded 2026-09-15：安装凭据机制已移除，见下文[决定更新（2026-09-15）](#决定更新2026-09-15)。）初始化完成永久关闭引导，不将默认密码用于恢复。
- 数据库与生命周期共同保证恰好一个管理员；移除新增管理员和身份升降级，不建设 RBAC 配置系统。
- 继续采用系统自动生成的不透明随机会话令牌和服务端会话记录，不引入 PASETO 或双令牌格式。令牌格式不扩散到业务，认证流程、撤销和权限也不依赖客户端声明。
- 第一版按产品需求支持密码后的邮件或短信验证码；明确其不抗钓鱼，不声明满足 NIST 高保证等级 MFA。未来认证提供方、二级验证提供方与投递实现分别扩展。
- 邮件使用 SMTP；通用 HTTP 投递提供受限字段映射，复杂签名与协议转换交部署方。禁止内嵌任意脚本或在线加载任意认证代码。
- 首次初始化不是正式登录；初始化成功后清除流程并返回登录页，重新完成密码和二级验证才能进入工作台。

## 替代范围与迁移

本决定替代 `CONTEXT.md` 及旧规格中的多管理员、首管只能离线创建、第一版无 MFA 等认证目标约束。保留现有密码安全基础、同源 Cookie 防护、服务身份隔离和敏感写事务复检。旧文档的 HTTP/SQL/配置形状仍是当前实现参考，不能据此声称新设计已经可用。

已有多管理员库必须在离线迁移中明确保留的管理员，其余保留稳定 ID 和历史引用转为 Operator；不得自动任选、删历史或给已有库重新启用 admin/admin。迁移后旧会话失效，未完成新初始化的用户不得进入工作台。备份、恢复、维护入口和测试须同时切换，不长期保留两套活动认证流程。

## 决定更新（2026-09-15）

2026-09-15 确认简化并已在代码落地：移除一次性安装凭据机制。上文取舍中“本机受限的一次性安装凭据用于阻止公开默认密码被抢先使用”由本决定取代（历史文本保留原义）：Quoin 不在产品内提供首次安装所有权证明，公开默认凭据在首次初始化完成前不具备服务端防抢占能力，**首次部署的访问边界由部署环境负责**（受控内网或受限管理网络，完成管理员初始化后再按需扩大可达范围）。

空库首启的 `admin/admin` 直接进入统一初始化流程（设置正式密码 → 投递配置 → 验证联系方式 → 返回登录页）。管理员恢复保持 CLI-only（停止长期进程、独占数据库、attached TTY），恢复后以 CLI 设置的临时密码登录并进入同一统一初始化流程。`install_credentials` 表保留在 `contracts/sql/schema.sql` 作为历史迁移权威（首装不再生成安装凭据；恢复用途的一次性凭据仍由该表承载）。本文其余决定不变。

**更正（2026-09-15，随后落地时确认）：** 上段关于 `install_credentials` 的保留叙述不再成立：该表已从 `contracts/sql/schema.sql` 完全移除，且没有任何已发布 Release 工件或迁移基线携带过该表（此前“历史迁移权威/遗留行仅作迁移数据”的说法不成立，已撤回）；恢复也不依赖任何存储的一次性凭据——`quoin admin recover`（`--mode password|factors`）经 attached TTY 设置或打印一次临时密码，不设单独有效期，恢复后的正常登录按凭据与账号状态机械分类为统一初始化流程，认证 wire 上不存在独立的 recovery 流程类别；初始化的完成以本流程内验证通过的收码渠道为准（流程投影 `factorVerified`），不依赖账户级渠道的历史验证状态。
