# 接入、观测与巡检使用指南

**状态：** 面向管理员（Admin）的主线使用指南，对应 [ADR-0004](adr/0004-plugin-capability-registry.md) 的插件化模型。主线链路已实现并由集成验证覆盖；真实部署验收进行中，逐项点击结果见 [plugin-real-deployment-acceptance.md](plugin-real-deployment-acceptance.md)，未全通过前不宣称完成。普通用户（Operator）只使用告警与 AI SRE，不进入本指南描述的管理页面；该边界由服务端逐请求强制。

## 总览

主线无需任何业务声明：接入验证并启用后即可观测、授权工具并运行巡检。

```
配置接入 → 验证（probe）→ 启用 → 默认来源级观测 + 默认基础巡检计划
                              ↓
             AI SRE 工具按 sourceRef 定来源 → Evidence → 巡检报告
                              ↓
        可选：业务视图（收窄范围）／浏览器插件显式启用（浏览器身份与 Journey）
```

## 接入管理

入口：运维中心 → **接入管理**（仅 Admin）。页面先展示支持的平台目录与已接入实例；当前目录为 Alertmanager、Kubernetes、Prometheus、Thanos，浏览器卡片仅在 browser 插件显式启用后出现。

1. **创建**：选择平台后进入该平台专属配置表单。地址、TLS、认证模式（`none`／HTTP Basic／Bearer）等按类型收集；秘密只提交一次，不回显、不进入 URL 或日志。同一平台可以有多个接入。
2. **验证**：新建接入先保持停用，点击验证会创建真实 probe Attempt；首次验证失败不会自动启用或触发该接入的采集。模型供应商的验证还会实测 streaming、tool call、取消与 Embedding 维度，通过后才允许启用。已启用接入的后续探测结果与启停状态是不同事实，不应将一次探测失败误写成自动停用。
3. **启用**：启用是接入生效的唯一门槛。启用事务内会自动创建该接入的**默认基础巡检计划**（仅人工运行，不产生定时模型费用），并开始默认来源级观测；创建失败会整体回滚，不会出现“已启用却无即用计划”。启用不要求业务系统或业务视图。
4. **停用与凭据轮换**：停用只阻止新派发；轮换创建新凭据代次并原子切换，旧代次按既定轮换语义退休。

## 来源观测

每个已启用接入的详情中有**观测资源**列表，明确区分“当前观测到 / 当前未观测到”及陈旧标注，并提供**刷新观测**。

- 观测身份 = 来源接入 + 对象类型 + 规范来源身份；跨来源同名对象不合并。
- 系统按默认周期自动观测，也可以手动刷新；同一接入同时只有一个观测 Run。
- 失败、截断或局部结果不会清空资源，也不会推断物理删除；“未观测到”只来自一次完整成功的观测。

## AI SRE 中的来源工具

对话与告警初步分析可以直接使用已启用接入的只读工具：`thanos_query`（PromQL 即时查询）与 `kubernetes_read`（当前已实现的受限 Kubernetes 只读操作，以冻结工具参数目录为准，不代表已交付全量资源发现或任意 get/list/logs）。

- 模型只提交 `query`、对象定位等人类可读参数；来源接入由系统按冻结授权解析。来源有歧义时，模型会用 `sourceRef` 指名接入，或向你追问。
- 模型看不到也选不了地址、凭据或连接配置；工具结果作为不可变 Evidence 保存，可在对话与告警详情中查看。

## 巡检

入口：运维中心 → **巡检**（仅 Admin）。计划独立于业务声明，直接绑定一个接入与一个插件模板。

**计划**：新建/编辑时选择接入、模板（当前为 `promql_instant`／`promql_range`，参数是封闭的 PromQL 表达式与窗口秒数）、范围与调度：

- 范围三选一：**整个接入**、**显式对象集合**（使用已观测对象的类型与来源身份）、**业务视图**。后两种在 Run 创建时冻结精确标签条件，采集前通过 PromQL AST 将条件注入每个向量选择器；缺失条件或未知范围拒绝执行。业务视图没有标签条件时不能创建范围 Run，需要全来源采集请明确选择“整个接入”。
- 调度可留空（仅人工运行）；填写标准五字段 cron 并选择时区即启用定时运行。定时巡检会触发模型报告费用，需要明确启用。
- 同一计划同时最多一个运行中的 Run；重叠的定时周期标记 `SkippedOverlap`，不补跑。

**运行与报告**：标题区“运行巡检”选择计划立即采证；Run 详情按状态与时间、检查结果（`ok/gap`、采证时间、Evidence）、分析状态与报告版本排列。

- 采证完成（`Completed`/`CompletedWithGaps`）只表示证据采集事实，**不表示系统健康**；gap 逐项如实记录。
- “重新分析现有证据”只创建新 Report 版本；“重新采集”创建新 Run 并引用旧 Run（`rerun_of`）。两者独立，不合并成含糊的“重试”。

## 业务视图（可选）

入口：运维中心 → **业务视图**（仅 Admin）。视图是对一个接入范围与明确 label 条件的可选组织，可附加业务说明；提供表单与 YAML 两种编辑同一对象的方式。

- 视图不拥有资源、凭据或额外权限，只用于收窄巡检对象等候选范围。
- 不创建视图也可以接收告警、观测资源、使用工具和运行基础巡检。
- 巡检计划按视图定范围时，仍固定与计划自己的接入相交，并在 Run 创建时冻结当时的视图内容；之后修改视图不影响已创建的 Run。

## 浏览器（显式启用）

默认部署不包含浏览器插件，Lintel 未注册时一切主线功能可用。需要浏览器自动化（人工登录身份、Journey、探索）时：

1. 在 Quoin 配置的 `enabledPlugins` 中加入 `browser`；
2. 部署 Lintel overlay（Kubernetes 见 `deploy/kubernetes/lintel.yaml`，Compose 使用 `compose.browser.yaml`）。

启用后在接入管理的浏览器卡片中按独立 `identity_key` 创建身份：配置起始 URL、认证探测与参数，由 Admin 发起人工登录并在探测成功后显式发布 profile。Cookie 与浏览器状态只保存在 Lintel 数据卷，不进入数据库或备份。历史业务系统绑定的身份以只读引用与显式迁移状态展示。
