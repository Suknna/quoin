# Quoin 统一认证设计

- 日期：2026-09-14。
- 状态：已落实为代码与机器契约；实现、迁移和隔离部署的实际验收结果见[实施计划](auth-audit-implementation-plan.md)及[验收记录](acceptance/auth-audit-20260915/README.md)；依据 [ADR-0005](adr/0005-unified-authentication-foundation.md)。
- 范围：登录、初始化、用户、二级验证、投递扩展、会话与接口准入。审计自动化与操作关联见已确认的 [ADR-0006](adr/0006-automatic-audit-and-operation-correlation.md) 及[审计设计](audit-design.md)，已落实为代码与契约，联合验收以实施计划为准。
- 本文解释认证边界与取舍；HTTP、SQL 和部署配置的精确字段以已同步的机器契约及部署手册为准。

## 1. 身份与用户生命周期

一个部署固定一个内置 `admin`，其余用户均为 `operator`。管理员具有全部业务及管理能力，不能删除、禁用或降级；不提供创建第二管理员、身份升降级、自定义角色、权限组或权限勾选。

操作员由管理员创建，只禁用不物理删除，稳定用户 ID 和登录名不变，显示名可修改。管理员指定其邮箱、手机号和临时凭据；操作员不能在初始化或登录时自行替换收码目标。管理员可以禁用、启用、重置操作员凭据或撤销其会话。启用不恢复旧会话。

数据库保证最多一个管理员，启动、初始化、迁移和恢复共同保证管理员存在。固定身份不代替对象归属与业务状态校验，操作员只能管理自己的账户和会话。

## 2. 系统首次启动与管理员初始化

空库首次启动自动创建唯一待初始化的 admin，初始密码为 admin。该弱默认密码只在初始化状态可被接受，不进入正式密码策略的例外列表，不签发工作台会话。已有库、重启、升级和恢复均不能重启默认密码。

公开默认密码不能证明部署所有权；Quoin 不在产品内提供首次安装所有权证明机制（2026-09-15 确认移除原设计的一次性安装凭据，见 [ADR-0005](adr/0005-unified-authentication-foundation.md) 决定更新）：公开默认凭据在首次初始化完成前不具备服务端防抢占能力，**首次部署的访问边界由部署环境负责**（受控内网或受限管理网络，完成管理员初始化后再按需扩大可达范围）。并发初始化只能有一个有效完成结果。服务未初始化时仅开放初始化所需入口及最小健康检查，业务与普通管理入口保持关闭。

管理员流程：

1. 使用公开默认凭据 `admin/admin` 登录，直接进入仅限初始化的短时流程。
2. 设置符合正式策略的新密码。
3. 配置并测试投递连接（部署已预配置时复用）。
4. 登记至少一种管理员邮箱或手机号，真实发送验证码并校验。
5. 原子完成初始化，永久关闭默认密码入口并清除流程。
6. 返回登录页；再次完成密码及二级验证后才进入工作台。

初始化阶段可以配置投递，但不能借此获得其他管理权限。初始化中断不能使未完成用户变成正常用户；草稿允许安全恢复，已完成步骤及新凭据不能因刷新或重启回退到默认密码。

## 3. 操作员初始化

1. 管理员创建账户，指定邮箱/手机及临时凭据。
2. 用户验证临时凭据，进入受限初始化流程。
3. 设置正式密码，验证管理员指定的至少一种联系方式。
4. 完成初始化并清除流程，返回登录页。
5. 使用新密码并完成二级验证，进入工作台。

初始化成功不自动登录。初始化未完成不能访问普通账户管理、业务、下载或流式入口。初始化流程有期限、限速和撤销能力；临时密码不另设过期计时器，但仅可进入初始化，正式改密或再次重置后失效。

## 4. 正常两步登录

密码验证通过仅创建短时认证流程，不创建完整 Session。二级页面展示脱敏联系方式，两个渠道均已配置并验证时可选择一个，不默认要求连续验证两个；不可输入任意新收件地址。

Quoin 生成和校验挑战，验证成功时原子消费挑战并创建完整会话。挑战绑定账户、认证流程、用途、收码目标版本与认证版本。密码、联系方式或用户状态改变时旧挑战失效。初始化的完成以本流程内验证通过的收码渠道为准（流程投影 `factorVerified`，派生自流程行而非账户级渠道状态）：账户级渠道此前的已验证状态（例如密码找回后的保留目标）不能替代本次流程的挑战，完成端点同样以此为准。

验证码短时有效、单次消费；失败次数跨重发累计，账户/目标/来源及全局发送校验都有界，并限制短信费用。低熵验证码不得仅保存易离线穷举的无密钥摘要；秘密不进入日志或持久命令结果。投递失败或延迟不能降级为密码单因素登录。只在流程与账户状态仍有效时接受验证码。

邮箱/短信可按需求用于第一版二级验证，但不抗钓鱼；邮箱不满足 NIST 带外认证要求，短信为受限方式。产品不得据此宣传符合高保证等级 MFA。挑战契约允许未来 TOTP/WebAuthn 等不同交互形态，不能固定为“所有因素都发送验证码”。

## 5. 会话权威

继续采用密码学安全随机源生成的不透明令牌，通过 Secure、HttpOnly、SameSite=Lax、Path=/ 的同源 Cookie 持有；服务端保存摘要与会话记录。随机源失败拒绝签发，唯一约束兜底，不回退可预测值。用户和部署方不用配置令牌。无 PASETO、JWT 或可配置令牌格式。

业务只接收当前认证结果，不解析令牌。服务端会话与当前用户状态决定身份是否有效；禁止永久快照角色作为权限权威。初始化、恢复、待二级验证和正式会话严格隔离。

保留空闲 12 小时、绝对 7 天默认值，按节流更新真实有效活动；SSE 心跳、无人使用的后台轮询不能无限续期，空闲期限不得超过绝对期限。保留多设备会话和按会话撤销。

修改/重置密码、禁用、联系方式或验证绑定变更撤销旧会话及挑战。敏感写提交前再次验证当前身份。SSE 等长连接在有界时间内感知失效，不仅连接时校验；已受理后台任务保留操作者引用，不因会话失效自动取消。

## 6. 管理员恢复

目标为部署侧交互式 `quoin admin recover`，通过停止长期进程、独占正确数据库并证明部署访问权执行；不要求恢复备份或人工编辑 SQL。密码不进入命令行、环境变量或普通日志。

- 仅忘记密码：通过 TTY 设置新的临时密码，不自动取消已有二级验证。
- 所有因素均不可用：重置全部收码因素与密码，生成仅在 attached TTY 打印一次的临时密码。

临时密码不设单独有效期；再次执行恢复会取代先前的临时密码。两种模式均撤销旧会话/挑战并记录恢复事实：服务重启后，管理员以该临时密码正常登录，凭据与账号状态机械分类为与首次安装完全一致的统一初始化流程，重新建立正式密码（全因素丢失时还需验证新联系方式），完成后返回登录页。认证 wire 上不存在独立的 recovery 流程类别。不得恢复 admin/admin、创建第二管理员或发放可绕过因素验证的普通会话。

## 7. 扩展契约

认证采用可信、显式注册并随版本交付的扩展，不是在线安装任意代码，不复用 AI 工具执行权限。

- 登录提供方：本地密码、未来 OIDC/GitHub，提供身份验证结果。
- 二级验证提供方：邮件/短信 OTP，未来 TOTP/Passkey，完成额外验证。
- 投递实现：SMTP、出站 HTTP Webhook，仅负责接受投递，不决定认证结果。

核心拥有流程、账户映射、限速、挑战生命周期与会话签发。新增提供方不修改这些编排规则，但可能新增适配代码并重新构建发布，不承诺任意厂商零代码接入。

外部身份绑定按 provider/issuer 与稳定 subject，禁止仅凭同名邮箱合并账户。管理员预建操作员，外部登录不得注册或提升管理员。GitHub 用户登录是 OAuth 与身份查询，不假装成通用 OIDC 配置；上游登录成功不能自动满足本地二级验证要求。

## 8. SMTP 与出站 HTTP Webhook

不强制部署 Novu、身份代理或其他网关平台。邮件复用 SMTP；短信或邮件可调用部署方已有通知接口。复杂厂商签名与协议转换交部署方自己的适配实现。

默认 HTTP 投递载荷示意：

```json
{
  "delivery_id": "unique-delivery-id",
  "channel": "sms",
  "recipient": "+8613800000000",
  "template": "login_verification",
  "variables": {"code": "123456", "expires_in_seconds": 300}
}
```

`2xx` 仅表示接受投递，不证明送达或用户验证成功；支持有些接口在 200 中返回业务失败的简单响应判断。无需入站认证回调。

部署可配置固定 URL、请求头的秘密引用、JSON/表单字段映射及固定占位符、简单成功条件。禁止任意脚本、Shell、循环、通用表达式、动态目标 URL 或厂商签名 DSL。模板必须采用结构化编码，不能直接拼接未转义收件地址和验证码。

默认 HTTPS，禁止自动重定向，限制目标主机/端口及敏感地址，显式允许所需私网网关；校验实际连接目的地以防解析变化绕过限制。只有部署或受保护管理员能修改配置。限制连接时长、响应大小和出站量。凭据沿用受保护秘密存储，不复制到审计、前端持久状态或普通日志。

投递目标是可信接收方，会获得收件地址和验证码；不用第三方平台不等于没有数据暴露。超时不能推断没有发送，仅在对方支持 delivery_id 去重时安全重试；有限重试不得超过挑战有效期，不宣称 HTTP 恰好投递一次。

## 9. 接口准入与前端

每个注册入口必须声明准入类别；未声明不能默认公开，注册/契约测试应失败。公开、受限流程、正常用户、管理员分别校验；受限流程凭据不能被普通会话解析器接受。对象归属与业务规则继续服务端执行。机器身份与用户会话不混用。

HTTP、文件下载、SSE、维护和未来扩展入口覆盖同一规则。保留现有 Cookie 同源/CSRF、安全响应头及敏感响应 no-store 防护。Huma 文档、OpenAPI、schema 路由继续默认关闭；以后启用须连同原始规范资源一起受管理员准入保护。

前端复用官方 shadcn `login-03` 认证卡片和 `InputOTP`，保持 Quoin 品牌；初始化、密码页和二级页面共用外壳，移除自助注册和未启用社交按钮。我的账户包含资料、验证方式与会话，系统管理包含用户管理；前端可见性不替代后端权限。

## 10. 迁移与验收边界

旧认证实现与相关规格、SQL、OpenAPI、配置、维护/恢复入口、mock 和测试已一次切换，不并行保留旧活动登录路径。已发布旧库有多个管理员时需明确选择保留主体，其余保留 ID/历史引用转 Operator；不自动任选、不物理删除、不重置为默认密码。该旧认证升级路径撤销旧会话，未完成新初始化者必须补齐。

另有通过精确 schema 摘要识别的未发布认证审计中间版本，其简化迁移只移除已取消的安装凭据和 recovery 流程数据，保留已有用户、有效会话、联系方式、业务与审计历史。两条迁移路径各有独立前置条件与测试，不能把中间版本保留会话的规则套用于旧单因素库；未知 schema 不自动迁移。

验收至少覆盖：默认凭据不能进入工作台（初始化完成前可被同网可达者抢先初始化，首次部署访问边界由部署环境负责）；并发初始化唯一完成；初始化中断可恢复；唯一管理员不变量；操作员目标不可替换；初始化完成返回登录；密码成功未发正式会话；重发不重置失败计数；挑战单次消费；投递失败不绕过；联系方式/密码变更撤销会话和挑战；所有入口无越权；会话续期不超过绝对期限；离线恢复不需要备份回滚；Webhook 目标与模板安全；审计无秘密。

审计依照 [ADR-0006](adr/0006-automatic-audit-and-operation-correlation.md) 与[审计设计](audit-design.md)合并实施：统一入口和执行器默认记录，认证流程持久保存 correlation_id，跨密码及二级验证请求继承；初始化后的重新登录建立新关联。不依赖业务手工 audit 调用，保留期及 schema 保护同步迁移。
