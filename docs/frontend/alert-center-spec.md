> **历史规格提示：** 本文仅记录告警中心重构时的前端范围和当时可用接口，非当前验收依据。[#95](https://github.com/Suknna/quoin/issues/95) 与 ADR-0002 已接受将平台内部故障以独立来源映射纳入统一告警读模型，并在运维中心增加接入管理和业务纳管；#102 已实现管理员关于页与独立平台故障来源，且不伪造 Alertmanager Occurrence；相关 API、SQL 与测试已同步，但不代表 #95 全部目标已经实现。本文其余历史范围、接口限制和验收记录只保留供追溯，不得据此重建 UI；当前告警实现是保留基线，前端验收以 [`ui-acceptance.md`](./ui-acceptance.md) 和当前规范为准。

## Problem Statement

当前告警工作台把实体列表放在导航侧栏，缺少独立的模块导航，列表与详情的层级不够清晰。告警初步分析入口与详情阅读割裂，“接入问题”混在日常告警视图中也容易让用户误解。用户希望参照提供的界面结构改善浏览与分析体验，同时严格使用现有后端数据与能力，不复制参考产品未受支持的业务操作。

## Solution

将告警中心重构为“图标导航 + 模块导航 + 统一列表”，单击告警后打开右侧覆盖式详情抽屉。模块导航包含“告警列表”和“故障复盘”。故障复盘暂显示可复用的“能力建设中”占位。告警详情内仅保留“AI 分析”Tab，进入时自动启动或复用现有初步分析，不设置 Ask AI 按钮，不提供聊天。将告警接入问题迁到管理模块。

采用 shadcn 官方组件与项目现有主题，复用现有接口和独立开发的模拟环境。此规格仅要求前端重构，不增加后端领域能力。

## User Stories

1. 作为工作台用户，我希望保留熟悉的图标导航，以便继续访问其他模块。
2. 作为告警处理用户，我希望在独立模块导航中选择告警列表或故障复盘，以便清楚理解所在位置。
3. 作为告警处理用户，我希望默认进入告警列表且当前菜单项高亮，以便立即浏览告警。
4. 作为告警处理用户，我希望切换当前和历史告警，以便区分 Firing 与 Resolved 的 Alert Occurrence。
5. 作为告警处理用户，我希望继续按现有业务系统条件筛选，以便聚焦相关告警。
6. 作为告警处理用户，我希望列表以一致方式展示标题、状态、次要信息、时间和受支持的操作，以便快速扫读。
7. 作为告警处理用户，我希望列表具备清晰的加载、空数据和请求失败反馈，以便区分等待、无结果与错误。
8. 作为告警处理用户，我希望单击列表项即可在覆盖式抽屉查看详情，以便不离开当前模块。
9. 作为告警处理用户，我希望选中项高亮，关闭详情后仍保留筛选条件，以便继续浏览。
10. 作为告警处理用户，我希望选中状态可通过 URL 恢复，且浏览器前进后退行为一致，以便刷新或分享当前详情。
11. 作为告警处理用户，我希望详情展示真实的描述、属性和观察记录，以便理解告警发生与恢复过程。
12. 作为告警处理用户，我希望界面不显示没有接口支持的认领、手动关闭等操作，以免被误导。
13. 作为告警处理用户，我希望首次进入 AI 分析 Tab 时自动发起初步分析，以便减少重复操作。
14. 作为告警处理用户，我希望再次进入 AI 分析时复用运行中任务或成功结果，以免重复提交任务。
15. 作为告警处理用户，我希望分析失败时能显式重试，并看到真实失败反馈，以便恢复操作。
16. 作为告警处理用户，我希望关闭详情不会取消分析，以便任务能继续执行。
17. 作为告警处理用户，我希望分析结果继续支持现有证据阅读能力，以便核查分析依据。
18. 作为告警处理用户，我希望 AI 分析只呈现一次性分析而非聊天界面，以便准确理解当前能力。
19. 作为用户，我希望进入故障复盘时明确看到“能力建设中”，以便不把未开放能力误认为没有报告数据。
20. 作为管理员，我希望从管理模块查看并确认告警接入问题，以便排查数据接收异常，而不干扰日常告警浏览。
21. 作为非管理员，我希望迁移后的管理入口继续遵循既有访问控制，以便角色边界不因样式重构而改变。
22. 作为键盘或窄屏用户，我希望详情抽屉可访问、可关闭且内容可滚动，以便正常完成浏览。
23. 作为前端开发者，我希望统一列表通过 items 与 columns 配置复用，以便后续接入复盘时不复制另一套列表样式。
24. 作为前端开发者，我希望“能力建设中”是可复用组件，以便其他未开放模块保持一致提示。
25. 作为前端开发者，我希望在现有离线模拟环境中验证全部新界面状态，以便不依赖后端部署进行样式开发。

## Implementation Decisions

### 布局和路由

- 最终选择覆盖式抽屉，取代最初的固定第四栏方案。未选中时只显示列表，不保留第四栏空占位。
- 最左图标导航保持现有行为。告警中心第二栏为约 w-56 的模块导航，包含“告警列表”和“故障复盘”；其右侧为完整列表内容区。
- `/alerts` 默认重定向至 `/alerts/list`；告警列表位于 `/alerts/list`，故障复盘占位位于 `/postmortems`。两个路由都属于告警中心，保留相同模块导航与全局告警选中状态。
- 使用 URL 查询参数 `id` 表示选中的 Alert Occurrence；保留现有当前/历史与业务系统筛选语义。单击打开，关闭清除选中参数但保留筛选，刷新及浏览器前进后退恢复相应页面状态。
- 使用 shadcn Sheet 构建右侧覆盖式详情抽屉，包含可访问标题、关闭操作、正确焦点管理及独立内容滚动。窄屏可使用接近全屏宽度，不强行并排压缩导航、列表和详情。
- 更新受影响的路由入口、内部链接、面包屑与测试，不为废弃布局保留重复实现。其他工作台模块不在本次重构范围。

### 统一列表与占位资源

- 通用 EntityList 以 props 接收 items、columns、选中状态和选择回调，不拥有告警请求或业务生命周期。
- item 至少提供稳定 id 与 title，可携带 badge（text、variant）、subtitle、time 及业务扩展字段。columns 配置支持标题、状态、次要信息、时间与操作的展示，各模块不复制不同视觉实现。
- 列表支持顶部 Tabs 和 Select 筛选入口、选中高亮、Empty、Skeleton 与请求失败/重试反馈。只有现有接口支持的字段与操作才展示；行内操作不得误触发详情选择。
- 本轮告警实际使用统一列表。故障复盘不伪造数据、不显示报告状态过滤或假操作；未来接入时复用相同组件。通过配置行为测试验证通用性，不为演示复用添加虚假业务模块。
- 提取基于 shadcn Empty 的 FeatureUnderConstruction 等价组件，默认标题“能力建设中”，支持必要的模块说明；不展示未经确认的上线时间，不与真实列表空状态混用。
- 使用官方组件组合，保持项目现有主题、语义色与原语库，不迁移 UI 基础库或套用新主题。

### 告警详情与初步分析

- 以真实 Alert Occurrence、属性及 Alert Observation 为数据来源。详情保留概览、时间线及现有数据支持的历史阅读；概览可采用描述/近期时间线与属性栏的左右布局，窄屏顺序堆叠。
- 历史内容不得虚构人员操作、分配历史或审计事件；若没有独立数据可与时间线区分，则合并展示而非制造重复或空洞 Tab。
- 不显示认领、手动关闭、负责人等无接口支撑的能力。Resolved 仍由上游 Alertmanager 数据驱动。
- 详情内仅设置“AI 分析”Tab，不再设置 Ask AI 按钮，不叠加第二个 AI 抽屉，不展示聊天输入框、不创建 Investigation。
- 只有用户进入 AI 分析 Tab 且确认不存在既有分析时才自动启动 Initial Analysis；打开普通详情不启动任务。
- 已有运行中任务则附着并展示当前任务；已有成功结果直接展示。切换 Tab、关闭重开、刷新以及快速连续操作不得因前端生命周期重复提交分析。
- 分析读取失败不是“没有分析”，不得在读取失败时自动创建任务。提供真实错误反馈和适当恢复入口。
- 失败提供显式重试；取消状态按现有接口语义展示，不自动重启。关闭抽屉不调用取消接口。若保留取消或重新分析操作，必须是现有接口支持的显式用户操作。
- 保留分析结果与证据阅读的既有能力，避免旧完成结果自动挡住正在执行的新任务。此次不新增对话，也不扩展原有调查模块。

### 接入问题迁移与契约边界

- 从告警中心的当前/历史过滤中移除“接入问题”，在管理模块增加“告警接入问题”入口。
- 迁移既有查看、确认和错误反馈，遵循管理模块既有访问控制；不新增管理员管理模块之外的导航层级。
- 保留后端异常隔离、原始接收记录、问题确认语义、历史、审计与 API。不删除身份冲突、指纹不匹配或数据截断等事实。
- 不增加数据库表、后端接口、报告状态机或业务权限模型。沿用独立前端开发发布与生产同源接口边界。
- 同步更新受影响的界面布局说明，领域术语继续区分 Alert Occurrence、Initial Analysis、Investigation、接入问题和未来故障复盘，不把报告或调查重命名为复盘。

## Testing Decisions

- 以现有应用级浏览器边界为主要验收点：通过页面交互、URL、可见状态和请求行为验证，不测试组件私有状态、Hook 调用次数或 CSS 类字符串。
- 复用现有 Playwright 离线模拟路由/告警/证据阅读覆盖及 MSW 场景基础设施。仅当浏览器用例不易覆盖配置组合或请求竞态时，补充现有 Vitest + Testing Library 模块级测试，不新建另一套测试框架。
- 路由验收：默认重定向、两项模块导航高亮、列表筛选、单击抽屉、关闭保留筛选、直接链接、刷新和浏览器前进后退。无效或不可访问的选中 id 显示错误/不存在反馈，可关闭返回列表。
- 列表验收：不同 columns 配置、可选字段缺失、选中高亮、空状态、加载态、失败恢复和行内操作不误触发选择。
- AI 验收：普通详情不发起分析；首次进入 Tab 发起一次；运行中/成功状态不重复提交；快速重复进入及关闭重开不会重复创建；读取失败不误创建；失败显式重试；关闭不取消；结果与证据可阅读。模拟响应遵循现有后端契约，不用静态假成功替代行为。
- 接入问题验收：告警中心不再显示入口；管理员可从管理模块访问并确认；非管理员遵循原管理访问限制；无后端数据删除或摄取逻辑变更。
- 占位验收：故障复盘显示“能力建设中”，没有虚假报告、编辑、保存、报告状态过滤或错误的后端请求；共享占位能以不同模块说明复用。
- 进行桌面及窄屏的浏览器视觉检查，检查导航层级、列表阅读密度、抽屉遮挡与滚动、AI 内容、长标题/长属性，并验证键盘关闭与焦点恢复。
- 沿用现有离线守卫：不访问真实后端或外部业务传输，没有未处理的 mock API 请求与页面异常。更新被路由与交互替代的旧用例，不无限叠加过时断言。
- 在可用时补充现有真实模式 smoke 验证；若环境不具备条件，明确报告跳过，不用模拟模式冒充真实后端通过。

## Out of Scope

- 实际故障复盘列表、文档详情、报告编辑/保存、状态时间线及后端能力建设。
- 告警认领、人工关闭、负责人、团队、行动项、评论与参考产品的其他未支持能力。
- Ask AI 按钮、多轮 AI 对话、新建或内嵌调查线程。
- 固定第四栏布局及未选中时的第四栏空占位。
- 删除告警接入问题后端模型、数据、异常隔离或历史审计。
- 全工作台所有列表的批量迁移、其他模块重设计、主题或 UI 原语库迁移。
- 后端数据库/契约变更，以及部署架构变更。

## Further Notes

- 本规格来自已结束的设计访谈；最终用户决定优先于最初“四栏”描述及参考图。参考图只用于信息层级和阅读体验，不要求像素级或配色复刻。
- “统一列表”是可复用组件约束，而不是要求本轮为尚不存在的复盘业务造数据。
- 测试方案沿用仓库已存在的最高层应用边界，是规格中的工程验收选择，不声称用户曾单独审批测试工具细节。
- 本次交付为规格发布，未实现页面，也未执行上述实施验收测试。
