# 告警中心布局重构：设计访谈记录

状态：设计访谈已结束，关键产品决定已确认；导航结构已按确认范围实现。

## 已确认范围

- 使用 shadcn 官方组件组合，保留项目现有主题，不复刻参考图的配色。
- 使用约 48–56px 的全局窄栏：品牌入口默认进入告警列表；窄栏始终直接提供带 tooltip 和 aria 标签的“运维中心”和“AI SRE”图标按钮，分别默认进入 `/alerts/list` 与 `/investigations`。管理员入口和用户菜单位于底部。
- 运维中心使用约 w-48–56 的共享模块导航，模块标题固定为“运维中心”，包含“告警列表、故障复盘、巡检、业务系统”；路由 `/alerts`、`/postmortems`、`/inspections`、`/business-systems` 分别唯一对应当前项。巡检和业务系统保留其菜单下方现有对象列表、筛选与操作；告警不重复其旧模块导航。
- 列表占据模块导航右侧内容区域。告警详情使用覆盖式抽屉，不采用固定第四栏。
- 通用 EntityList 接收 items 和 columns，统一标题、状态 Badge、次要信息、时间、操作的视觉结构；支持 Tabs、Select 筛选、选中态、加载态与空状态。不加入接口不支持的业务字段或操作。
- 故障复盘本轮仅保留导航，点击展示基于 shadcn Empty 的“能力建设中”。将该占位封装为可复用资源；不伪造复盘数据、报告状态、编辑或保存能力。复盘详情和实际复盘列表延后。
- 告警详情抽屉内仅保留“AI 分析”Tab，不再设置重复的 Ask AI 按钮，不叠加第二个 AI 抽屉。不提供聊天输入、多轮对话，不新增调查线程。
- “接入问题”从告警中心迁到管理模块，保留既有查看与确认能力，以及后端摄取、异常记录、历史和 API。
- 当前告警恢复由上游驱动，没有认领或手动关闭接口。本轮不展示这些参考图操作。

## 分析交互规则

- 首次进入“AI 分析”Tab 且没有既有分析时，自动发起现有初步分析。
- 已有运行中任务时展示当前任务，不重复提交；已有成功结果时直接展示结果。
- 失败时提供显式“重试”。重新分析仅在现有接口支持时作为独立显式操作，不因打开界面自动重复执行。
- 关闭详情抽屉不自动取消分析。

## 实现采用的常规交互

- 单击列表项打开详情抽屉，选中项写入 URL，刷新可恢复详情。
- 关闭详情保留列表筛选条件；未选中时显示列表，不保留固定第四栏空占位。

## 现有事实

- AI SRE 是独立全局模块；“对话”保留现有调查路由，“知识”作为其内部导航，二者在 `/investigations` 与 `/knowledge` 中唯一对应当前项。运维中心使用共享模块导航与告警覆盖式抽屉，不需要固定第四栏；管理和账号路由不选中任一模块。
- 告警状态为 Firing / Resolved，观察记录可用作真实时间线。
- 当前无独立故障复盘领域对象和 API。

本记录是界面设计范围，不将界面组件或路由等实现细节写入领域术语表。访谈已收敛，没有剩余产品问题；本记录不代表页面实现已经完成。
