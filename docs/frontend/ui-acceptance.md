# 前端 UI 验收规范

本文件是每次前端调整的权威 UI 验收要求。它补充而不替代领域、权限、接口和可访问性规格；自动化测试、类型检查或构建成功不能替代这里要求的真实浏览器检查。

## 组件与交互约束

1. **层次与容器：** 每个页面或弹窗最多一层卡片。并列的一级 Card 可以存在；内部必须通过留白和 `Separator` 组织层次，禁止 Card 嵌套 Card，也不得用带边框或背景的裸容器伪装第二层卡片。
2. **可点击行：** 可点击行必须至少同时具备以下两项：图标、hover 变色、chevron。行仍必须使用语义化按钮或链接，并可通过键盘操作；视觉提示不能替代可访问名称、焦点或原生语义。
3. **数据展示：** 数据密集内容使用 `Table`；列表流使用 `Item`；无数据使用 `Empty`；状态使用 `Badge`。禁止用裸 `div` 仿制这些组件；纯布局容器可以使用 `div`。

## 每次调整的真实浏览器自查

每次前端调整都必须在真实浏览器中完成并保留下列检查的截图和操作证据；自动化可以辅助生成场景和截图，但测试通过不能替代实际视觉与交互复核：

- [ ] 眯眼看截图：能否一眼分出标题层、内容层、操作层？
- [ ] 只用鼠标扫页面：能否不看代码就找全所有可点的元素？
- [ ] 数据边界：0 条 / 1 条 / 50 条 / 超长文本，各长什么样？
- [ ] 窗口拉到 1920 CSS px 宽，内容是否无限拉伸？
- [ ] 页面里同一层级的标题，字号字重是否完全一致？

逐项检查本次调整的页面与弹窗；无相关数据列表的项目标注不适用并说明理由，不能默认勾选。宽屏必须采用明确的内容宽度或列宽策略，同级标题复用统一排版样式。未通过项修复后复查。

页面未实际调整时无需虚构或补做上述页面检查；文档-only 变更应明确记录为未执行页面检查。证据应保存在对应变更的可审阅交付记录中，至少包含截图、操作步骤或录屏定位，以及所检查页面/状态。
