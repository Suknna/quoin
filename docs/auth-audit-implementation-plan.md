## 阶段 2：统一上下文、执行器和审计基础

实现小型 `execution`（注册、类型化 Context、事务和命令结果）与独立 `audit`（保存、查询、保留）。下移/复用现有台账，避免依赖 auth 形成循环。

- [x] 根入口创建不可变上下文，子操作继承；缺失上下文拒绝，不默认系统身份。
- [x] 执行器独占事务提交：权限复检→幂等→业务→自动台账/审计→提交。
- [x] 使用保存点或等价回滚保证先写后拒绝不提交部分修改；认证失败计数是显式状态变更。
- [x] 审计失败回滚；重放不重复成功；未变更统一记录；提交未知不伪造失败。
- [x] 使用SQLite实际只读连接，验证 QueryContext 执行写入/RETURNING也失败，不只是隐藏 Exec。
- [x] 事务包装不暴露原连接或 Begin/Commit/Rollback，防止逃逸；组合操作复用同事务，不嵌套开事务造成单连接死锁。
- [x] 注册覆盖 Huma和原生路由，声明语义，自动提供主体/时间/结果/关联。
- [x] AST/类型依赖检查禁止业务另开数据库、取原连接、提交或手写审计；启动/迁移仅最小机制例外，CLI业务不整体豁免。
- [x] 受限类型、真实只读行为、架构和公共行为测试共同证明，不以grep代替。

完成门槛：新测试业务不写audit调用仍有记录；缺失注册/上下文、数据库绕过、先写后拒绝、审计故障、重放和组合操作的反向测试通过。
