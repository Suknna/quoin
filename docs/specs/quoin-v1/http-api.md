# Quoin v1 — HTTP 与实时 API 规格（http-api.md）

**状态：Draft**

**CATEGORY 前缀：`HTTP`**（SPEC-TRACE-002）

**Non-normative：** 本文件是 Quoin v1 HTTP API 的跨请求语义、认证/授权、命令幂等、错误模型、分页、HTTP 快照、SSE 回放、对话流、上传下载、取消 fence 与 noVNC 升级关系的规范性说明。路由、方法、请求/响应字段、头部、状态码与可机械表达的 HTTP 契约只由 [`contracts/openapi.yaml`](contracts/openapi.yaml) 承载；本文件**不复制完整字段清单**（SPEC-AUTHORITY-002），引用时使用相对路径与稳定 operationId。规范条款来源为 [`CONTEXT.md`](../../../CONTEXT.md) 稳定标题、[Issue #3](https://github.com/Suknna/quoin/issues/3)、[Issue #18](https://github.com/Suknna/quoin/issues/18)（证据 commit `prototype/issue-18-http-streaming@34a46c70e9931dfe43d5b418ea35c85ba0a754f2`）、[Issue #9](https://github.com/Suknna/quoin/issues/9)（`persistence.md` DATA-* 条款）与 [Issue #8](https://github.com/Suknna/quoin/issues/8)。

## 1. 范围与权威

- **HTTP-SCOPE-001 —** `contracts/openapi.yaml` **MUST** 是 Quoin v1 HTTP 路由、方法、输入输出结构、状态码、头部与安全声明的唯一机器权威；本文件 **MUST NOT** 定义与 OpenAPI 冲突的字段或路由；OpenAPI 中无法机械表达的跨请求语义（认证、幂等、回放、fence 裁决、授权边界）由本文件拥有（SPEC-AUTHORITY-001/003）。（来源：Issue #8「权威源与事实所有权」）
- **HTTP-SCOPE-002 —** 全部 HTTP 路由 **MUST** 位于 `/api/v1` 之下（SPEC-VERSION-002）；所有 JSON 时间戳 **MUST** 为 RFC3339 UTC 字符串；64-bit 技术 locator **MUST** 在 JSON 与路径参数中序列化为十进制字符串（DATA-IDENT-002），**MUST NOT** 使用 JSON 数字，超出 JS 安全整数仍必须按字符串处理（DATA-IDENT-001，Q9.1 A）。稳定用户 key（业务系统 key、连接名、告警源 key 等）**MUST** 以字符串原样传输。（来源：Issue #8「版本与冻结」、Issue #9 Q9.1）
- **HTTP-SCOPE-003 —** OpenAPI 只描述前端→Quoin 的 HTTP 面。Stele 告警接入（`relay_id` 幂等、`204` 语义）属于 `runtime-protocol.md`（#11）与 `persistence.md` DATA-ALERT-* 的契约；Plinth/Lintel 任务、lease、文件上传与浏览器会话走 gRPC 控制面（`contracts/runtime.proto`），**MUST NOT** 通过 HTTP API 复制。本文件只承担浏览器 UI 的 HTTP 面。（来源：CONTEXT「Stele」「服务身份」、Issue #8「机器契约目录」）

## 2. 认证与会话

- **HTTP-AUTH-001 —** 浏览器 **MUST** 只通过 `__Host-quoin-session` Cookie 携带 32-byte 随机 opaque Session bearer（Secure、HttpOnly、SameSite=Lax、Path=/）；HTTP API **MUST NOT** 接受 Authorization 头、查询参数或请求体中的 bearer；服务端 SQLite 只保存 bearer 的 SHA-256 digest（DATA-AUTH-003），认证时对收到的 bearer 求 digest 后查询，digest 与 raw bearer **MUST NOT** 写入日志或审计。（来源：CONTEXT「同源 Web 会话」「模型调用边界」）
- **HTTP-AUTH-002 —** 登录 `login` **MUST** 使用统一失败信息（401），**MUST NOT** 区分用户不存在、密码错误与账号禁用；密码按 NFC 规范化后校验 15–128 Unicode 字符，弱密码检查与有界失败冷却由部署层执行；登录成功 **MUST** 签发新 Session（空闲 12 小时、绝对 7 天），Set-Cookie 同时设置过期属性，并返回当前用户（含 `passwordChangeRequired`）。（来源：CONTEXT「本地账号认证」）
- **HTTP-AUTH-003 —** 服务端 **MUST** 在每个受保护请求上读取当前 User 状态（`enabled`、`role`、`auth_revision`）；Session 记录签发时 revision 用于比较，**MUST NOT** 缓存角色快照作为授权依据（DATA-TX-002）。账号禁用、角色变化、Admin 重置密码 **MUST** 在事务中递增 `auth_revision` 并撤销该用户全部 Session；`resetUserPassword` 只有在该事务提交后才返回更新后的 User 与 `revokedSessionCount`，旧 bearer 的下一次 HTTP/SSE/WebSocket 认证必须因 revision 不匹配失败。用户自行改密撤销除当前外的其他 Session 并更新当前 Session revision。（来源：CONTEXT「本地账号认证」）
- **HTTP-AUTH-004 —** 登出 `logout` **MUST** 撤销当前 Session 并清除 Cookie；`revokeOwnSession` 只允许撤销当前用户的其他 Session，**MUST NOT** 允许撤销当前请求所用 Session；`revokeUserSessions`（Admin）撤销目标用户全部 Session。撤销 **MUST** 立即关闭对应 Session 的 SSE 与 WebSocket，**MUST NOT** 自动取消已受理后台任务（DATA-ATTEMPT-004）。（来源：CONTEXT「同源 Web 会话」）
- **HTTP-AUTH-005 —** 全部写请求 **MUST** 受 Go `CrossOriginProtection` 保护；WebSocket 握手另校验 `Origin` 等于部署配置的公共 Origin；**MUST NOT** 提供带凭据的跨域 CORS（HTTP-NOVNC-002）。SSE 只读接口 **MUST NOT** 允许跨域。（来源：CONTEXT「同源 Web 会话」）
- **HTTP-AUTH-006 —** `password_change_required=1` 的用户登录后 **MUST** 只获得受限 Session：**MUST** 只能调用 `getCurrentUser`、`changeOwnPassword` 与 `logout`；其余全部操作 **MUST** 返回 403（`code=password_change_required`），并包含指向改密入口的 `remediation`。成功改密 **MUST** 在同一事务清除标志（DATA-AUTH-001/002），此后请求按正常 Session 授权。（来源：CONTEXT「管理员离线恢复」、DATA-AUTH-002）
- **HTTP-AUTH-007 —** Session 登出、撤销、过期或账号禁用时，服务端 **MUST** 立即终止该 Session 的 SSE 与 WebSocket 连接；后台任务继续执行并保留原操作者引用（DATA-ATTEMPT-004）。（来源：CONTEXT「同源 Web 会话」「执行尝试」）

## 3. 权限与授权

- **HTTP-PERM-001 —** 全部登录用户 **MUST** 可读全部运维数据（告警、调查、巡检、知识、业务系统、连接状态、审计、Runtime 状态、备份列表以外的数据）；读接口 **MUST NOT** 按业务系统隔离。（来源：CONTEXT「Operator」「Admin」）
- **HTTP-PERM-002 —** Operator **MUST** 可执行：发起/取消/重试分析与巡检、处理调查/反馈/知识（含候选编辑、确认、排除）、为已有 Browser Identity 重新登录并发布 generation、确认接入问题以外的诊断操作；Admin **MUST** 为 Operator 超集，另拥有用户/Session、业务系统与 Label Contract、连接与秘密、模型供应商、巡检配置发布、Runtime 替换、告警源凭据、备份与安全设置的全部写操作（权限矩阵）。授权 **MUST** 在服务端按当前 User 状态裁决，**MUST NOT** 依赖前端隐藏入口（HTTP-AUTH-003）。（来源：CONTEXT「Operator」「Admin」）
- **HTTP-PERM-003 —** 写权限校验 **MUST** 与业务写在同一 SQLite 事务内完成（DATA-TX-002）：账号变更事务先提交则业务写冲突（409），业务写先提交则有效。（来源：CONTEXT「本地账号认证」、DATA-TX-002）
- **HTTP-PERM-004 —** 禁用或降级最后一个有效 Admin **MUST** 冲突（DATA-TX-014）；离线创建/重置首个 Admin 走停机命令（`quoin admin reset-password`），**MUST NOT** 提供 HTTP Bootstrap 或邮件找回路径。（来源：CONTEXT「管理员离线恢复」）

## 4. 领域写命令与幂等

- **HTTP-COMMAND-001 —** 所有经认证外部调用者发起的领域写命令 **MUST** 由客户端生成用户不可见的 `client_command_id`（8–128 个 `[A-Za-z0-9_-]`），按 `(principal, client_command_id)` 唯一（DATA-COMMAND-001）；OpenAPI 中 `CommandRequest`/`CancelRequest` 等写请求体与 multipart 上传（附件、staging Artifact、业务系统 YAML、Label Contract YAML）**MUST** 包含该字段；仅 `login`、`logout`、`changeOwnPassword` 与一次性秘密 reveal 操作（`revealAlertSourceCredential`，HTTP-COMMAND-008；`revealRuntimeRegistrationToken`，HTTP-COMMAND-012）不属于领域写命令，**MUST NOT** 要求该字段。Stele `relay_id` 与 Runtime `attempt_id + connection_epoch` **MUST NOT** 改造成 HTTP 命令键（CONTEXT「领域写命令契约」）。（来源：CONTEXT「领域写命令契约」）
- **HTTP-COMMAND-002 —** 请求摘要 **MUST** 覆盖全部语义请求字段，**包括** `expectedRowVersion`、`expectedHeadMessageId`、`expectedCurrentPublishedVersionId`、`expectedCurrentConfigVersionId`、`expectedRevision` 等并发前提（DATA-COMMAND-002）；摘要 **MUST NOT** 包含 nonce、时间戳等非语义字段。修改当前状态或 current 指针的命令 **MUST** 携带 `expectedRowVersion`（DATA-COMMAND-005）——持久化模型使用其他显式前提的命令（消息 head、发布版本、候选/批次 revision）**MUST** 携带对应字段；纯追加创建（发送首条消息、创建调查、导入批次、知识反馈）**MUST NOT** 强制 expected version。无 head/无当前已发布版本时 `expectedHeadMessageId`/`expectedCurrentPublishedVersionId`/`expectedCurrentConfigVersionId` **MUST** 显式传 `null`（OpenAPI `NullableLocatorId`，JSON Schema 2020-12 `anyOf [LocatorId, null]`），**MUST NOT** 使用空串或 "0"。（来源：CONTEXT「领域写命令契约」、Issue #9 Q9.1 确认）
- **HTTP-COMMAND-003 —** 相同 `client_command_id` 且相同摘要重放 **MUST** 返回原确定性结果（200/201/202 + 原对象），**MUST NOT** 重新执行；相同 ID 但不同摘要 **MUST** 返回 409（`code=command_id_reused`）（DATA-COMMAND-003）。重放响应与首次响应在状态码与正文上 **MUST** 一致（幂等读路径，见 HTTP-COMMAND-004）。唯一例外：一次性秘密命令（HTTP-COMMAND-008 的告警源 Bearer 与 HTTP-COMMAND-012 的 Runtime 注册令牌）的 reveal handle 与 raw 秘密 **MUST NOT** 被持久化，因此重放响应 `revealAvailable`/`registrationTokenAvailable` 恒为 `false` 且不含对应 handle；重放 **MUST NOT** 重新创建凭据/令牌；首次响应丢失时客户端 **MUST** 以新 `client_command_id` 重新执行创建/替换，**MUST NOT** 尝试恢复旧秘密。命令权威结果、状态与对象身份在重放中保持完全一致。（来源：CONTEXT「领域写命令契约」、Issue #18 证据、HTTP-COMMAND-008/012）
- **HTTP-COMMAND-004 —** 确定性业务拒绝（版本冲突、fence 拒绝、校验失败）**MUST** 以 `outcome='rejected_known'` 短事务持久化命令结果与审计后返回对应 4xx（DATA-COMMAND-004/DATA-AUDIT-004）；基础设施失败或提交结果未知 **MUST NOT** 被伪造为成功或失败——调用方 **MUST** 复用同一 `client_command_id` 重试，服务端对已提交命令返回原结果、对未提交命令重新执行（幂等提交模式）。一次性秘密命令（HTTP-COMMAND-008/012）按同一规则裁决：已提交命令的重试返回非秘密元数据（`revealAvailable=false`/`registrationTokenAvailable=false`、无对应 handle），raw 秘密 **MUST NOT** 因重试而再次可得，客户端需以新 `client_command_id` 重新执行创建/替换。（来源：CONTEXT「领域写命令契约」、HTTP-COMMAND-008/012）
- **HTTP-COMMAND-005 —** 取消 **MUST** 通过独立幂等 cancellation fence 命令（`CancelRequest`：`clientCommandId` + `expectedRowVersion`）提交，**MUST NOT** 使用 transport abort/AbortController 或断线表达领域取消（Issue #18 证据：本地取消不会取消领域任务）。成功结果与 fence 按 SQLite 提交顺序裁决（DATA-TX-005）：成功先提交则取消 **MUST** 返回已完成对象（200，非 409）；取消先提交则迟到结果不产生有效消息/Report/Candidate，只留审计。fence 与 transport detach 并发时 **MUST NOT** 停留在 `fenced` 中间态，终态必须为 `Cancelled`。（来源：CONTEXT「执行尝试」、Issue #18、DATA-TX-005）
- **HTTP-COMMAND-006 —** 已受理后台操作 **MUST** 在创建业务对象与 Attempt 的事务提交后立即返回（202 + 持久化对象）；接受/失败不得依赖异步完成；命令重试语义与 Attempt 幂等键（`attempt_id`）分离（DATA-ATTEMPT-004）。（来源：CONTEXT「调查与巡检工作区」「执行尝试」）
- **HTTP-COMMAND-007 —** 同一命令重放**不得**因携带原 `expected_*` 值而误冲突：`expectedRowVersion` 等在摘要中参与一致性判定，但服务端 **MUST** 先按命令键查重；已提交命令直接返回原结果，只有新命令才执行版本前提校验（DATA-COMMAND-002/003）。（来源：Issue #9 Q9.1 确认）
- **HTTP-COMMAND-008 —** 一次性秘密（告警源 Bearer）**MUST** 采用两段式流程：① 幂等领域写命令（`createAlertSource`/`rotateAlertSourceCredential`，携带 `client_command_id`）在同一事务创建来源/凭据，响应只含非秘密元数据 `AlertSourceCredentialMetadata`（`sourceKey`/`credentialId`/`revealAvailable`）；仅首次实时响应 **MAY** 携带内存中短生命周期、单次使用的 `revealHandle`（`revealAvailable=true`）。② 独立一次性 reveal 操作（`revealAlertSourceCredential`，POST，Admin-only）**MUST** 只接受该 handle，**MUST NOT** 接受 source/credential ID；消费一次后返回 raw Bearer 并立即失效。handle 与 raw Bearer **MUST NOT** 持久化——SQLite、`client_commands`、日志、审计、Artifact 与响应快照均禁止；handle 无效、已消费或过期 **MUST** 返回 410，会话无效 401，角色不足 403。命令重放（HTTP-COMMAND-003/004）**MUST** 返回 `revealAvailable=false` 且无 handle，**MUST NOT** 重新创建凭据；首次响应丢失 **MUST** 以新 `client_command_id` 轮换。reveal 操作是唯一携带一次性秘密的 HTTP 响应面（`bearerToken` 只允许出现在 `RevealCredentialResult`）；Runtime 长期服务 token 只经已认证 gRPC 控制面下发/轮换（HTTP-COMMAND-012），**MUST NOT** 进入 HTTP 响应。（来源：CONTEXT「告警源凭据投影」「服务身份」）
- **HTTP-COMMAND-009 —** 告警源凭据吊销（`retireAlertSourceCredential`，Admin）**MUST** 是携带 `clientCommandId` 与 `expectedRowVersion` 的领域写命令（HTTP-COMMAND-001/002）：同一事务内校验凭据属于路径中的来源（跨来源 404）且状态为 `Active`（已 `Retired` 凭据对新命令返回 409 `row_version_conflict`，DATA-ALERT-009），写入 `retiredAt` 并递增凭据 `rowVersion`；相同命令 ID 重放 **MUST** 返回原结果（HTTP-COMMAND-003）；吊销与成功先提交的 Delivery 按 DATA-TX-003 提交顺序裁决。吊销是 HTTP 管理面操作，**MUST NOT** 通过 Stele/Runtime 协议表达。（来源：CONTEXT「告警源凭据投影」、DATA-ALERT-009）
- **HTTP-COMMAND-010 —** 连接创建/轮换输入 **MUST** 使用按 `type` 封闭的判别联合（OpenAPI `ConnectionInput`，`additionalProperties: false`，三个变体：`ThanosConnectionInput`/`KubernetesConnectionInput`/`ModelProviderConnectionInput`）：非秘密配置字段与秘密字段在同一变体内声明，未知字段、跨类型字段与任意 `configJson`/`secretJson` 对象 **MUST** 被拒绝（DATA-CONN-005）。秘密字段（`password`/`kubeconfig`/`apiKey`）**MUST** 只存在于请求内存，服务端加密为 `CredentialGeneration` 后丢弃；响应 **MUST** 只返回服务端生成的非秘密类型化投影——`ConnectionSummary` **MUST** 是按 `type` 封闭的顶层 `oneOf`（`ThanosConnectionSummary`/`KubernetesConnectionSummary`/`ModelProviderConnectionSummary`，外层 `type` 与 `config` 变体由同一对象强制一致），**MUST NOT** 回显客户端输入或秘密（HTTP-AUTH-001）。轮换命令（`rotateConnectionCredential`）**MUST** 携带 `expectedRowVersion`；连接与告警源 enable/disable、`replaceRuntimeSlot`、`publishBrowserProfileGeneration`、`stopKnowledgeReuse`、`excludeKnowledgeCandidate`、`resetUserPassword`、`acknowledgeIntakeIssue`（DATA-ALERT-011）使用 `VersionedCommandRequest`/等价前提（`clientCommandId` + `expectedRowVersion`）。（来源：CONTEXT「连接」「模型调用边界」、Issue #10 复审）
- **HTTP-COMMAND-011 —** 语义 no-op（请求字段存在但值未变化，如 `displayName=displayName`、`enabled=enabled`）**MUST** 冻结为幂等成功：返回当前权威对象，**MUST NOT** 执行 UPDATE、递增 `row_version`、产生 SSE 变更事件或重复写审计成功事件；命令账本仍按 HTTP-COMMAND-003/004 记录并重放确定性结果。与 HTTP-COMMAND-007 一致，命令键查重优先于任何字段比较。（来源：Issue #9 Q9.1 确认、Issue #10 复审）
- **HTTP-COMMAND-012 —** Runtime 一次性注册令牌（bootstrap 秘密）**MUST** 复用 HTTP-COMMAND-008 的两段式 reveal 模式：① 幂等领域写命令 `replaceRuntimeSlot`（携带 `clientCommandId` + `expectedRowVersion`，HTTP-COMMAND-010）在同一事务先确认 fence（DATA-RUNTIME-001b：目标 slot 无绑定该 slot 的 active Attempt `Assigned`/`Running`/`Cancelling`，且 `lintel` 无状态为 `Queued|WaitingForCapacity|Starting|Running|AwaitingReconnect` 或虽已终态但 `stop_confirmed_at` 为空的 Browser Operation），否则 **MUST** 返回 409 `active_conflict` 且 **MUST NOT** 先行吊销（DATA-RUNTIME-001）；通过后单条 UPDATE 置 `revoked` 并清空 `current_credential_id`/`pending_credential_id` 指针，AFTER 触发器 `trg_runtime_slots_replace_retire_all` 自动置 `retired_at` 并递增 `row_version`（被引用行在指针清空前禁止手动 retire，DATA-RUNTIME-001/002），响应只含非秘密元数据 `RuntimeSlotReplacement`（`slot`/`state=revoked`/`currentGeneration=0`/`rowVersion`/`registrationTokenAvailable`）；仅首次实时响应 **MAY** 携带内存中短生命周期、单次使用的 `registrationTokenHandle`（`registrationTokenAvailable=true`）。② 独立一次性 reveal 操作 `revealRuntimeRegistrationToken`（POST，Admin-only）**MUST** 只接受该 handle，**MUST NOT** 接受 slot 或凭据 ID；消费一次后返回绑定 slot 与 generation 的 raw 一次性注册令牌并立即失效——响应为 `RuntimeRegistrationTokenRevealResult`（`slot`/`generation`/`registrationToken`，`generation` 必填，RUNTIME-REG-002）。handle 与 raw 注册令牌 **MUST NOT** 持久化——SQLite、`client_commands`、日志、审计、Artifact 与响应快照均禁止；handle 无效、已消费或过期 **MUST** 返回 410，会话无效 401，角色不足 403。命令重放 **MUST** 返回 `registrationTokenAvailable=false` 且无 handle，**MUST NOT** 重新生成令牌；首次响应丢失 **MUST** 以新 `clientCommandId` 重新执行替换。注册令牌由 Runtime 经 gRPC `RegisterRuntime` 一次性消费换取长期服务 token（`runtime-protocol.md` #11）：`RegisterRuntimeRequest` 必须回显 reveal 结果中的 `generation`，Quoin 内存令牌记录同时绑定 slot 与 generation，任一项不匹配即拒绝（`FAILED_PRECONDITION`/`PERMISSION_DENIED`，RUNTIME-REG-002/007）；长期 token 轮换走已认证控制流两阶段流程（DATA-RUNTIME-002），**MUST NOT** 进入 HTTP。（来源：CONTEXT「服务身份」、Issue #11 前置审计）

- **HTTP-COMMAND-013 —** `probeModelProvider` 是 Admin 发起的幂等后台命令，只适用于 `type=model_provider` 的 current revision/generation；创建或轮换已先原子切换 current pair，但在 probe 成功前普通模型工作与 enable 均被阻断：同一事务创建 `type=model_provider_probe, scope_type=connection` 的 Execution Attempt 和冻结输入后返回 202 `AttemptSummary`。Plinth supervisor 必须真实执行 Chat streaming、native/multi Tool Call、取消、usage/request ID 与 Embedding/dimension 测试；只有成功 probe 才能提交 current `model_provider_capabilities`。已启用的 Model Provider 不能直接切换到未探测 pair；v1 轮换固定为 disable → 原子切换 current revision/generation → probe → enable（期间不承载新模型工作），**MUST NOT** 绕过能力门静默保留旧 pair。`enableConnection` 对 model_provider 必须要求 current revision/generation 已有成功能力行，否则返回 409 `active_conflict`；`/v1/models` 目录读取或 SDK 构造成功均不满足启用条件。（来源：Issue #13、DATA-CONN-006/007）

## 5. 错误模型与状态码

- **HTTP-ERROR-001 —** 所有非 2xx 响应 **MUST** 使用单一 `application/problem+json` 错误包络（OpenAPI `ErrorModel`）：稳定 `code`、面向人的普通语言 `message`（先说明影响与恢复方式）、可选 `requestId`、`retryable`、`fieldErrors[]`（`path`/`reason`/`remediation`）与冲突时的 `conflict`（对象类型、当前 locator、当前 `rowVersion`/head/version）。响应 **MUST NOT** 暴露堆栈、内部路径、Provider 原始错误正文或任何秘密（HTTP-AUTH-001）。（来源：Issue #8「错误模型」授权、CONTEXT「模型调用边界」）
- **HTTP-ERROR-002 —** `code` **MUST** 是稳定机器可读字符串且按语义分类：`malformed_request`、`unauthenticated`、`forbidden`、`not_found`、`row_version_conflict`、`head_conflict`、`current_pointer_conflict`、`command_id_reused`、`active_conflict`、`identity_busy`、`authentication_required`、`authentication_probe_unavailable`、`artifact_commit_failed`、`resource_expired`、`payload_too_large`、`unsupported_media`、`validation_failed`、`rate_limited`、`unavailable`、`password_change_required`；同一语义 **MUST NOT** 出现多个 code。`message` 允许面向语言本地化，`code` 不允许。（来源：CONTEXT「领域写命令契约」、Issue #14）
- **HTTP-ERROR-003 —** 状态码映射 **MUST** 为：400 请求语法错误；401 未认证/Session 无效（统一信息）；403 权限不足或受限 Session；404 资源不存在；409 版本/幂等/active/identity/authentication/最后一个 Admin 冲突；410 Artifact 正文已过期或 SSE 游标过期；413 请求体/文件超限；415 不支持的媒体类型；422 语法有效但领域校验失败；429 部署级速率限制；500 已受理操作的内部不可恢复提交失败（如强制 Artifact commit 失败）；503 维护中、Runtime 或 probe 技术不可用；429 与可预估恢复窗口的 503 **MUST** 携带 `Retry-After`。取消/结果竞态 **MUST** 返回已提交的当前权威状态，**MUST NOT** 用 500/409 伪装。（来源：Issue #8、Issue #14、CONTEXT「执行尝试」）
- **HTTP-ERROR-004 —** 409 响应的 `conflict` **MUST** 是按 `code` 判别的闭合联合。既有 command/row/head/current/runtime-slot 变体保持；`identity_busy` **MUST** 使用 `IdentityBusyConflict`，强制当前 `browserOperationId`、`operationKind`、`occupiedSince`（身份锁取得时间），不得伪造 row version；`authentication_required` 可只返回 identity locator 与当前 revision/generation。`active_conflict` 继续用于非浏览器通用 active 对象，Browser Identity 占用不得复用该 code。`detail` 为人类说明，`retryable` 表示同一命令键重试是否安全。（来源：CONTEXT「领域写命令契约」、Issue #14）
- **HTTP-ERROR-005 —** `retryable=false` 的失败 **MUST NOT** 被自动重试（如 422 校验失败、403 权限、409 确定性拒绝）；`retryable=true` 且非幂等读接口的瞬态失败（429、503、网络中断）**MUST** 由调用方使用同一命令键有界重试（HTTP-COMMAND-004）。幂等只读 API 对瞬态错误 **MUST** 有界重试并记录物理尝试（DATA-ATTEMPT-005）。（来源：CONTEXT「执行尝试」「领域写命令契约」）
- **HTTP-ERROR-006 —** 登录、改密与所有写请求 **MUST** 受部署级速率限制与 Argon2 并发限制；429 响应 **MUST** 带 `Retry-After`。（来源：CONTEXT「本地账号认证」）
- **HTTP-ERROR-007 —** 503（维护中或依赖不可用）**MUST** 声明在下列操作上：全部 SSE/流端点（`streamAlertEvents`/`streamTaskEvents`/`streamInvestigationMessage`）、全部上传/下载（staging/附件/配置/Artifact/备份）、备份触发、Runtime slot 替换、连接创建/轮换/启停、Model Provider 真实能力探测、模型供应商模型列表（外部 `/v1/models` 调用）、浏览器登录/WebSocket/发布 generation、以及创建或派发 Execution Attempt 或依赖外部系统的写命令（分析/调查/巡检的发起、取消、重试、Undo、重新分析、重新采证、知识导入批次创建与确认）；纯本地只读元数据操作（列表/详情读取、设置读取）**MUST NOT** 声明 503。429 **MUST** 声明在全部写请求与登录/改密上（HTTP-ERROR-006）。OpenAPI 状态码矩阵与本条 **MUST** 一致（HTTP-VALIDATION-001）。（来源：Issue #8、CONTEXT「执行尝试」）
- **HTTP-ERROR-008 —** Runtime/worker 的封闭拒绝枚举不得由 HTTP 层猜测或降级为任意字符串：`AttemptRejectReason.NO_CAPACITY` 保持 Attempt Assigned 并按内部有界策略重试，`INPUT_UNSUPPORTED|INTERNAL` 封存为 `provider_unavailable`；未知 numeric/`UNSPECIFIED` 是协议错误并封存为 `worker_protocol_error`。Browser/Upload/Model failure 同样必须使用 `runtime.proto` 明确枚举及 `runtime-protocol.md` 的逐项映射；只有显式 `INTERNAL` 分支可进入 503 `unavailable`，不得设置“未知值默认失败原因”。（来源：Issue #13、RUNTIME-TASK-004、DATA-ATTEMPT-002、RUNTIME-ERROR-001）

## 6. 分页与列表

- **HTTP-PAGE-001 —** 列表接口 **MUST** 使用不透明游标分页（`cursor` 参数 + `nextCursor` 响应字段），**MUST NOT** 使用 offset 分页；游标 **MUST** 绑定过滤器与排序（跨排序/过滤变化视为无效），底层使用稳定排序键 + locator 构成键集边界。除非本规范另有明确排序，默认键固定为 `(id DESC)`；告警固定 `(last_state_change_at DESC, id DESC)`，Investigation 消息固定 `(created_at ASC, id ASC)`，Provider 模型目录固定 `(model_id ASC)`。游标载荷 **MUST** 绑定 operationId、规范化过滤器摘要、排序方向、最后 sort value 与 locator；游标失效 **MUST** 返回 400（`code=malformed_request`），客户端重新从首页读取。（来源：Issue #8「分页」授权）
- **HTTP-PAGE-002 —** `limit` **MUST** 有默认值 50 与最大值 200；超上限 **MUST** 截断或 400，**MUST NOT** 静默忽略；空列表 **MUST** 返回空 `items` 且无 `nextCursor`。（来源：Issue #8）
- **HTTP-PAGE-003 —** 告警列表排序 **MUST** 按 `last_state_change_at`（Quoin commit 时间）倒序，**MUST NOT** 按来源时间排序（DATA-IDENT-004）；Resolved 从 Firing 默认视图移除，但已打开详情 URL 继续可读并明确标记已恢复（CONTEXT「告警列表与详情」）。（来源：CONTEXT「告警列表与详情」「告警观察」）
- **HTTP-PAGE-004 —** 分页游标 **MUST** 绑定过滤器与排序键（HTTP-PAGE-001），单次遍历 **MUST NOT** 重复返回同一行；遍历期间的并发插入、删除与排序键变化 **MUST** 表现为位置移动或下页重读——键集游标只保证不重复与稳定排序，**MUST NOT** 承诺无丢失：新插入或排序前移的行可能在本页缺失、在下页或下一次遍历出现；客户端按 row version 幂等应用并在需要一致视图时重新读取快照（HTTP-SSE-003）。（来源：CONTEXT「实时投影」）
- **HTTP-PAGE-005 —** 以 `list` 为前缀的 operationId **MUST** 全部使用游标分页（`cursor`/`limit` 参数 + `{items, nextCursor}` 包络），包括 `listProviderModels`（供应商模型目录）与 `listOwnSessions`；详情/状态/快照响应内部只能嵌入**有界**数组（数量由配置或同一聚合单次执行固定，如 `SetupResponse.items`、`InspectionRunDetail.checks`、`KnowledgeDetail` 的版本计数）与计数/引用字段；**无界**追加集合（Occurrence 观测、Occurrence 的 Initial Analysis/调查历史、Initial Analysis 的 Attempt 历史、Inspection Run 的报告版本、Investigation 的消息/Attempt/Tool Call 历史、Connection 的 revision/generation 历史等）**MUST NOT** 嵌入详情响应，**MUST** 以独立游标分页子资源提供（`listAlertMatchedResources`、`listAlertObservations`、`listInitialAnalyses`、`listOccurrenceInvestigations`、`listInitialAnalysisAttempts`、`listInvestigationMessages`、`listInvestigationAttempts`、`listAttemptToolCalls`、`listInspectionReports`、`listConnectionRevisions`、`listCredentialGenerations`、`listKnowledgeVersions`、`listAlertSourceCredentials`），详情只返回对应 `*Count`。（来源：Issue #8「分页」授权、Issue #10 复审、Issue #13）
- **HTTP-PAGE-006 —** 快照列表（`listAlerts`/`getTaskSnapshot`）**MUST** 使用与快照 seq 绑定的短有效期游标：首响应生成服务端签名的 opaque 游标（绑定首页 `snapshotSeq`、键集位置、过滤器/排序与有效期），后续页 **MUST** 回传与首页**相同**的 `snapshotSeq` 并查询同一语义下的成员集合；客户端 **MUST** 以首页 `snapshotSeq` 建立 SSE（`after`/`Last-Event-ID` 见 HTTP-SSE-003），分页期间发生的变更由事件回放补齐（T1/T2/T3 无漏更新）。游标过期 **MUST** 返回 410（`code=resource_expired`），客户端重新从首页读取；游标伪造/篡改 **MUST** 返回 400（`code=malformed_request`）。（来源：CONTEXT「实时投影」、Issue #18 证据、Issue #10 复审）
- **HTTP-PAGE-007 —** 任务快照（`getTaskSnapshot`）**MUST** 是有界集合：只包含 active 任务对象（`initial_analysis`/`execution_attempt`/`inspection_run`/`tool_call`/`knowledge_import_batch`/`knowledge_candidate`/`browser_operation`/`config_test_run` 中状态非终态者）与当前用户已终态但**尚未查看**（`user_viewed` 投影）的任务对象；用户打开或标记查看后，终态任务离开快照。`items` **MUST** 按 HTTP-PAGE-006 游标分页遍历；快照**绝不**包含历史 Report/Candidate/Attempt 等长期对象的全量集合。（来源：CONTEXT「调查与巡检工作区」「后台任务提示」、Issue #10 复审）

## 7. HTTP 快照与 SSE

- **HTTP-SSE-001 —** 影响告警列表的事务 **MUST** 在同一 SQLite 事务产生单调递增 `alert_change_seq`（`alert_change_log.id`，DATA-SSE-001）；最新行（`MAX(id)`）由触发器保留、**MUST NOT** 被 GC 删除，因此 `high_water` 永不回退（DATA-SSE-009）。HTTP 快照（`listAlerts`）**MUST** 返回 `snapshotSeq` = 当前最大 `alert_change_log.id`（空库为 "0"）且每个 Occurrence 携带 `rowVersion`；快照分页游标绑定该 seq（HTTP-PAGE-006）。（来源：CONTEXT「实时投影」、DATA-SSE-001/009）
- **HTTP-SSE-002 —** `streamAlertEvents` **MUST** 为 `text/event-stream`：每个变更发送 `event: change`、`id: <alert_change_seq>`、`data: {"seq":"…","type":"created|state_changed","occurrenceId":"…","rowVersion":…}`（`seq` 为十进制字符串，`ChangeSeq`）；事件 **MUST** 携带 `id:` 行（重连基础）。游标过期按两种边界处理（HTTP-SSE-003）：响应头写出前已判定过期（last-seen 谓词，HTTP-SSE-009）**MUST** 返回 410 problem+json 且不写流；流已建立后判定过期 **MUST** 发送 `event: resync_required`、`data: {"type":"resync_required"}` 并关闭连接，**MUST NOT** 返回 410。响应 **MUST** 设置 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`，代理缓冲 **MUST** 被禁用（Issue #18 未覆盖 ingress，需生产验证，见 HTTP-VALIDATION-004）。（来源：CONTEXT「实时投影」、DATA-SSE-001/002）
- **HTTP-SSE-003 —** 客户端建立 SSE 前 **MUST** 先读 HTTP 快照并以 `after=snapshotSeq` 建立；重连 **MUST** 使用 `Last-Event-ID`（存在时**优先于** `after`）；服务端回放游标之后的**有界**派生变更；重复投递安全：客户端 **MUST** 按 `seq` 与 `rowVersion` 幂等应用（重复事件忽略、版本落后才重新读取详情）。游标过期由 last-seen 谓词判定（DATA-SSE-009）：`high_water > 0` 时 `cursor < high_water AND cursor < oldest_available - 1`；`high_water = 0` 时仅 `cursor = 0` 有效——过期时**MUST** 返回 `resync_required`（头前 410 / 流内事件）并重新读取完整快照（HTTP-SSE-002/008）。（来源：CONTEXT「实时投影」、Issue #18 证据）
- **HTTP-SSE-004 —** SSE 变更流可丢弃、可重建，**MUST NOT** 成为告警历史权威源（DATA-SCOPE-003）；日志按部署配置保留有界窗口（GC 可 DELETE，禁止 UPDATE，DATA-SSE-002）。（来源：CONTEXT「实时投影」）
- **HTTP-SSE-005 —** 心跳 **MUST** 使用 SSE 注释（`: comment`）形式，**MUST NOT** 被持久化、**MUST NOT** 携带业务数据；客户端 **MUST** 忽略未知事件类型；详情数据在 row version 变化后重新读取，事件**绝不**携带完整对象正文（DATA-SSE-003/005）。（来源：CONTEXT「实时投影」「调查与巡检工作区」）
- **HTTP-SSE-006 —** `streamTaskEvents` **MUST** 镜像告警契约：任务快照由 `getTaskSnapshot` 提供（`snapshotSeq` = 当前最大 `task_change_log.id`，最新行由触发器保留，DATA-SSE-009；`items` 为有界任务引用集合，HTTP-PAGE-007），任务详情接口（`listInvestigations`/`getInvestigation`、`listInvestigationAttempts`、`listAttemptToolCalls`、`listInspectionRuns`/`getInspectionRun`、`getInitialAnalysis`、`getKnowledgeImportBatch`、`getConfigTestRun` 等）由权威对象携带 `rowVersion`，`task_change_log` 与状态变化同事务派生（DATA-SSE-004）；事件 `data` 为 `{"seq":"…","objectType":"…","objectId":"…","changeType":"created|state_changed","rowVersion":…}`（`seq` 为十进制字符串，`ChangeSeq`）；`objectType` 限定为 `initial_analysis`、`execution_attempt`、`inspection_run`、`inspection_report`、`tool_call`、`knowledge_import_batch`、`knowledge_candidate`、`browser_operation`、`config_test_run`（DATA-SSE-004）。`tool_call` 事件由客户端按 `objectId` 在所属 Attempt 的 `listAttemptToolCalls` 投影中幂等刷新；短暂 Runtime `AttemptProgress.stage` 不持久化，也不进入此 SSE。（来源：CONTEXT「调查与巡检工作区」、DATA-SSE-004/005/006、Issue #13）
- **HTTP-SSE-007 —** 任务事件 **MUST** 只传对象类型/ID、变化类型与 row version，不直接传状态或阶段正文；客户端按版本重新读取权威详情。只有本身持久化阶段字段的对象（如 Config Test）才能在详情中恢复阶段；Plinth `AttemptProgress.stage` 是活动执行观察者的瞬态显示提示，刷新后由 Attempt 状态与 `listAttemptToolCalls` 时间线恢复，不得伪造或持久化该提示。token delta、逐字输出与高频动画 **MUST NOT** 进入 SSE 或持久化（DATA-SSE-005；最终输出只在持久化后作为对象内容读取）。（来源：CONTEXT「调查与巡检工作区」、Issue #13）
- **HTTP-SSE-008 —** 进入页面 **MUST** 先读 HTTP 快照再建立 SSE（T1/T2/T3 无漏更新，Issue #18 证据）；断线重连 **MUST** 有界回放，游标过期回 `resync_required` 后重读完整快照（HTTP-SSE-003）。（来源：CONTEXT「实时投影」、Issue #18）
